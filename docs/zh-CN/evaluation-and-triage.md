# 评测、归因与迭代协议

[简体中文](evaluation-and-triage.md) | [English](../en/evaluation-and-triage.md)

状态：当前共享协议，2026-09-02。

规范修订：`2026-09-02.4`。

## 用途

本文是测试、失败归因、修改、回归和 Prompt-only 停止条件的唯一所有者。

不要在角色定义与条件编译中各复制一套完整测试流程。这两个阶段只执行自己的静态检查，真实证据统一路由到这里。

## 评测层级

### 1. 定义审查

审查 `ROLE_SPEC`，不要求目标平台：

- 身份与 Canon 在所选范围内可靠；
- 人格特征能追溯到动机、价值、敏感点、防御和修复方式；
- 关系位置、代价、边界与渐进变化自洽；
- 表达来自人格，而不是固定台词或泛化标签；
- 用户偏好与角色必然行为已经区分；
- 未知项与冲突版本仍然可见；
- 平台工具、正则、动态状态和模型补丁没有进入语义源。

失败返回 `define`。

用户提供已有角色卡、没有运行失败，只要求审查或优化时，使用 `audit` 的 static 路径，并返回 `evidence_basis: static` 的 `TRIAGE_RESULT`。只有用户要求修复，且静态证据指向 Prompt 所有的缺陷时才修改。

对应静态 `EVIDENCE_RECORD` 通过引用、版本和哈希标识被审对象，使用 `observed_behavior: none` 与 `reproduction: not-applicable`，不得虚构运行证据。

### 2. 便携构建审查

根据 `ROLE_SPEC` 审查 `PORTABLE_ROLE_PROMPT`：

- 已接受的角色语义得到保留；
- 只假定能够立即输出普通文本；
- 不承诺工具、记忆、媒体、引用、延迟、主动发送、取消或投递确认；
- 不包含平台标签、精确 Schema、正则或动态上下文；
- 在 Prompt 正文之外明确标注尚未按运行条件编译；
- 它是唯一临时注入的角色 Prompt，未来会被最终构建替换而不是叠加；
- 存在可恢复的 `BUILD_RECORD`。

失败返回 `define` 或便携构建步骤。

### 3. 条件编译审查

根据 `ROLE_SPEC`、`PRESERVATION_MAP` 与 `RUNTIME_PROFILE` 审查 `FINAL_ROLE_PROMPT`：

- 只存在一个目标 Prompt；
- 保留 `must_preserve`，并遵守 `must_not_add`；
- 运行档案足以支持“已按条件编译”的主张；
- 不存在不支持的能力；
- 不包含精确宿主 Schema、正则、动态上下文和重复注入；
- 不包含作者资产、研究术语、评分与逐轮算法；
- 私聊行为针对具体角色，而不是统一短答模板；
- Prompt 长度来自必要决策，而不是累积修补；
- Prompt 吸收的每项运行事实、来源标记、层级事实、渲染规则、安全事实或能力都满足 `compile_ready`；
- 存在可恢复的 `BUILD_RECORD`。

失败返回 `compile` 或运行档案所有者。

### 4. 真实集成与真人验收

在实际目标环境中测试，并固定：

- 精确模型与提供商版本；
- 宿主与消息层级；
- System 注入顺序；
- 工具、记忆、媒体管线与渲染；
- 上下文与初始状态；
- 采样参数和用户输入。

只改变正在评测的 Prompt 或作者方法。

评估可观察行为，不要只测试模型能否复述已写规则。自然测试消息应接近真实私聊，并以现实比例包含普通歧义、随口残句、换话题、情绪、媒体、分歧和自然沉默。

避免轨迹持续围绕搜索、注入、边界或角色卡已明确写出的事实出题。这类测试主要测量规则检索，还可能让 Prompt 对测试本身过拟合。

### 5. 能力审计

确认时间、状态、来源身份、工具、媒体、延迟、主动发送、取消、记忆和投递确实由宿主提供。

失败返回宿主，不要增加角色规则模拟缺失的实现保证。

## 可观察失败分类

### 定义失败

- 人格模糊、角色之间可互换；
- 动机或边界冲突；
- Canon 或关系位置错误；
- 表达无法追溯到人格；
- 把用户偏好写成角色无法避免的行为。

### 编译失败

- 普通社交聊天中出现助手语气；
- 展示性交付偏置：为证明理解而追加复述、解释、建议、夸奖、安慰或问题；
- 语义闭合偏置：强迫残句、表情包或梗图变成一个完整的旧话题命题；
- 无充分证据的关系跃迁、承诺或完整照顾流程；
- 机械气泡数量、固定微型回复或重复表面口癖；
- 用户、平台任务、记忆、工具、引用与媒体之间来源混淆；
- Prompt 膨胀、规则重复或作者术语进入模型上下文。

### 宿主失败

- 混合或可伪造来源标签被当作权威；
- 缺失或陈旧状态被当作当前事实；
- 沉默、延迟、主动发送、取消或投递确认并未实现；
- 媒体封装丢失动作方向与归属；
- 渲染或气泡拆分意外改变可见消息。

### 非 Prompt 原因

- 模型指令遵循或多模态能力限制；
- 采样波动；
- 评审偏好与已接受角色逻辑冲突；
- 证据不足或一次性异常输出。

## 证据记录

修改前，按 `output-contracts.md` 记录最小证据：

- 精确条件；
- 实际可见输入；
- 预期与观察到的行为；
- 具体失败信号；
- 复现次数与证据强度；
- 一个主要假设。

使用脱敏摘录，不要保存凭据或不必要的私聊内容。

## 归因

返回一个主要分类：

```text
definition_fault
compilation_fault
host_contract_fault
model_limit
sampling_variance
preference_mismatch
insufficient_evidence
```

可以记录多个促成因素，但下一轮只验证一个主要假设，以保留因果归因。

单次异常样本默认是 `insufficient_evidence`。可以把 `sampling_variance` 作为待验证假设，但在多次独立会话支持前，不得把它写成已确定原因。

## 修改规则

1. 修改拥有该问题的源资产：`ROLE_SPEC`、`RUNTIME_PROFILE` 或编译规则；
2. 重新构建 Prompt，不依赖对上一版输出的直接补丁；
3. 只做观察证据支持的修改；
4. 除非用户授权，否则保留已接受的 Canon、人格、关系、表达与边界；
5. 不把一次好坏样本变成普遍规则；
6. 优先删除、明确归属和简化优先级，而不是增加例外；
7. 记录版本、假设、修改源、环境、结果，以及当前只经过作者审查、模型测试或真人验收中的哪一步。

用户只要求诊断时，返回 `TRIAGE_RESULT`。用户明确要求修复，且证据充分支持 Prompt 侧原因时，在同一次作者工作中完成对应修改并重新构建。宿主、模型、采样、偏好和证据不足只能得到诊断结果，不能强行转成 Prompt 修改。

## 回归

修复后重新运行：

- 能够复现失败的最小案例；
- 未受影响的普通聊天案例；
- 与改动有关的来源边界案例；
- 路由波动可能存在时，至少一个独立新会话。

不能因为测试句子的表面措辞改变就宣布成功。需要确认底层失败结构减少，同时没有引入冷漠、随机忽视、固定短答或角色辨识度丢失。

## Prompt-only 停止条件

出现以下情况时，停止继续添加 Prompt 规则：

- 缺失要求属于宿主状态、来源、工具、时间、媒体、调度或投递；
- 同一条清楚规则仍因模型能力而失败；
- 新规则主要是在复述旧规则或修复低概率例子；
- 一个案例的改善反复造成普通聊天退化；
- 只剩单次样本或个人偏好证据；
- Prompt 复杂度已经成为比原问题更大的失败来源。

此时应更换模型、修改宿主、调整采样、收集更强证据或接受剩余方差。

## 效果报告

只报告：

- 精确模型与宿主条件；
- Prompt 与运行档案版本；
- 实际修改内容；
- 哪些可观察失败增加或减少；
- 重复次数与真人验收状态；
- 剩余模型和宿主限制。

不要把角色定义质量和运行条件编译的改善合成一个普遍 Skill 分数，也不要把不同模型或平台的绝对分数当作同一种 Prompt 效果。
